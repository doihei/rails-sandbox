## i18n（国際化）規約

このプロジェクトは `rails-i18n` を使用し、`ja` をデフォルトロケール、`en` をフォールバックとして運用する。

### ロケールファイルの構成

```
config/locales/
  ja.yml              # 共通キー（app_name, nav, flash, article_status, activerecord）
  en.yml              # 同上・英語
  devise.ja.yml       # Devise システムメッセージ（日本語）
  devise.en.yml       # Devise システムメッセージ（英語フォールバック）
  articles/
    ja.yml            # articles.* キー（日本語）
    en.yml            # articles.* キー（英語）
  comments/
    ja.yml            # comments.* キー（日本語）
    en.yml
  tags/
    ja.yml            # tags.* キー（日本語）
    en.yml
```

- コントローラ単位でサブディレクトリに分割する。新しいコントローラを追加するときは `config/locales/<controller>/ja.yml` を作成する。
- Rails はデフォルトでは1階層しか読まないため、`config/application.rb` に以下の設定が必要（設定済み）：
  ```ruby
  config.i18n.load_path += Dir[Rails.root.join("config", "locales", "**", "*.{rb,yml}")]
  ```
- `ja` に翻訳が見つからない場合は自動的に `en` へフォールバックする（`config.i18n.fallbacks = true`）。

### キー構成の方針

```yaml
ja:
  app_name: "Rails Sandbox"       # アプリ共通

  articles:                        # コントローラ名
    index:                         # アクション名
      title: "記事一覧"
    form:                          # パーシャル名
      title_label: "タイトル"

  flash:
    article:
      created: "記事を作成しました"

  nav:
    logout: "ログアウト"

  article_status:                  # モデルのステータス値
    draft: "下書き"
```

### View での使い方

**Lazy lookup（推奨）**: アクション・パーシャルに対応するキーを自動解決する。

```erb
<%# articles/index.html.erb → ja.articles.index.title %>
<h1><%= t('.title') %></h1>

<%# articles/_form.html.erb → ja.articles.form.title_label %>
<%= form.label :title, t('.title_label') %>

<%# comments/_comment.html.erb → ja.comments.comment.delete %>
<%# comments/_form.html.erb    → ja.comments.form.submit %>
<%= button_to t('.delete'), ... %>
```

パーシャルはファイル名（先頭の `_` を除いた部分）がキー階層に入る。アクション名と異なる場合（`_comment` など）は `<controller>.<partial_name>.*` に解決される点に注意。

**絶対パス**: レイアウトや共通部品など、コントローラスコープが合わない場合に使う。

```erb
<%# layouts/application.html.erb %>
<%= t('app_name') %>
<%= t('nav.logout') %>
```

### Controller での使い方

```ruby
redirect_to @article, notice: t("flash.article.created")
```

### 動的キー（ステータスバッジなど）

```erb
<%= t("article_status.#{article.status.value}") %>
```

### ViewComponent での使い方

コンポーネントの Ruby ファイル（`.rb`）内では `t()` ヘルパーは使えない。`I18n.t()` を使う：

```ruby
def label
  I18n.t("article_status.#{@status.value}")
end
```

コンポーネントのテンプレート（`.html.erb`）内では通常の `t()` が使える。

### ActiveRecord バリデーションエラー

バリデーションの `message:` オプションにハードコードせず、`activerecord.errors.models` 配下に定義する：

```yaml
ja:
  activerecord:
    errors:
      models:
        article_tag:
          attributes:
            tag_id:
              taken: "はすでにこの記事に付いています"
```

モデル側では `message:` を省略する：

```ruby
validates :tag_id, uniqueness: { scope: :article_id }
```

Rails は `:taken` キーで `activerecord.errors.models.<model>.attributes.<attr>.<key>` → `activerecord.errors.models.<model>.<key>` → `activerecord.errors.messages.<key>` の順にルックアップする。

### 新しいキーを追加するときの手順

1. コントローラ名に対応するサブディレクトリのファイル（例: `config/locales/articles/ja.yml`）に日本語テキストを追加する
2. 同じファイルの `en.yml` に英語テキストを追加する
3. `app_name` / `nav` / `flash` / `article_status` / `activerecord` などアプリ共通のキーはルートの `ja.yml` / `en.yml` に追加する
4. Devise 関連のメッセージは `devise.ja.yml` / `devise.en.yml` に追加する
5. View / Controller で `t()` を使って参照する
